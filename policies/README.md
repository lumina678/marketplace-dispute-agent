# 版本化规则库

本目录中的规则是为项目演示人工编写的**虚构平台规则**，不是任何现实平台条款，也不构成法律意见。

## 选版规则

政策必须由确定性代码选择，禁止 Agent 自行选择“最新版”。

1. 读取交易快照的 `paid_at`。
2. 按 `policy_id` 和案件范围筛选候选版本。
3. 使用半开区间 `effective_from <= paid_at < effective_to`；`effective_to=null` 表示没有上界。
4. 必须恰好匹配一个版本。
5. 零个或多个版本匹配时，停止自动调查并转人工，不猜测版本。
6. 将选中的 `policy_id`、`version`、`paid_at` 和选择时间固定到案件；后续政策更新不改变已固定版本。

规则引用格式：

```text
marketplace.description_mismatch@2.0.0#DM-REMEDY-01
```

## 当前版本

| 版本 | 生效区间 | 主要差异 |
| --- | --- | --- |
| `1.0.0` | 2025-01-01 至 2026-01-01（不含） | 收货后 72 小时申报；申诉期 72 小时；建议金额高风险阈值 1000 元 |
| `2.0.0` | 2026-01-01 起 | 申报和申诉期均扩展到 120 小时；强化设备身份关联要求；高风险阈值调整为 2000 元 |

第二十步新增三个独立政策族，仍按交易 `paid_at` 选择唯一版本：

| 政策族 | 当前版本 | 专属边界 |
| --- | --- | --- |
| `marketplace.missing_parts` | `1.0.0` | 约定内容、签收内容、发货前装箱和有来源的退款金额；核心部件或内容冲突转人工 |
| `marketplace.empty_package` | `1.0.0` | 重量链、运单、卖方打包和买方首次开包；不把承运责任直接写成卖方责任 |
| `marketplace.shipping_damage` | `1.0.0` | 发货前状态、包装、签收损坏和报损时间；因果、延迟报损或承运责任转人工 |

对应文件位于 `policies/missing_parts/`、`policies/empty_package/` 和 `policies/shipping_damage/`。规则 ID 使用 `MP-*`、`EP-*`、`SD-*` 前缀，基础校验器会要求每个政策族都包含定义、举证、证据、处置、证据不足和升级规则。

## 修改要求

- 已生效文件不可原地修改；任何内容变化都创建新版本。
- 新版本不得与同一 `policy_id` 的已有生效区间重叠。
- 删除或改名规则时，必须保留旧版本以支持历史案件重放。
- `DRAFT` 版本不能被案件选中。
- 每个规则的 `rule_id` 在同一版本中唯一。
- 规则引用的 `required_evidence_refs` 必须存在于同一文件的 `evidence_requirements`。

运行 `python3 scripts/validate_foundation.py` 可检查上述结构和区间约束。
