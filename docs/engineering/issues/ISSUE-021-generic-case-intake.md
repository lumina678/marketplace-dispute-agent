# ISSUE-021：通用模拟案件接入

## 背景

前二十步已经具备调查、Skill、Guard、审核、执行和申诉闭环，但案件仍主要依赖种子脚本。外部使用者无法通过稳定 API 创建交易、导入交易前材料、提交争议并冻结可重放的调查基线。

PR-020 尚未合并到 `main`，因此本 Issue 暂时在 `feat/generic-case-intake` stacked branch 上开发。PR-020 合并后，PR-021 必须 rebase 到最新 `main` 并把目标分支改为 `main`。

## 目标

- 创建模拟交易；
- 导入唯一的商品争议基线快照；
- 原子批量导入交易聊天；
- 原子提交争议和一个或多个 Claim；
- 上传带原文和结构化事实的文字证据；
- 冻结交易、商品、聊天、Claim 和初始证据；
- 生成可验证的 Intake Manifest Hash；
- 冻结后仍允许已有补问和申诉通道追加新证据，但禁止修改初始基线；
- 新接入案件可直接进入 Router、Skill Workflow 和人工审核闭环。

## 验收标准

- [ ] 所有写接口使用显式业务 ID，重复相同请求返回幂等复用；
- [ ] 相同 ID 携带不同内容返回 `409 CONFLICT`；
- [ ] 交易双方必须引用已登记的 BUYER/SELLER；
- [ ] 商品和聊天只能由 ADMIN 导入；
- [ ] 聊天批次最多 500 条，任一冲突时整批不写入；
- [ ] 交易参与方只能提交本方 Claim 和本方证据；
- [ ] 文字证据保存原文、来源、哈希、关联 Claim 和 extracted facts；
- [ ] 冻结前必须存在交易、一个商品基线、至少一条聊天、Claim 和唯一 Skill 路由；
- [ ] 冻结使用 `expected_state_version` 防止并发覆盖；
- [ ] 冻结时按 `paid_at` 固定唯一政策版本；
- [ ] 冻结时自动把商品和聊天快照转换为 SYSTEM Evidence；
- [ ] 冻结后商品、聊天和初始文字证据接口拒绝写入；
- [ ] Manifest 能检测冻结材料被数据库外部修改；
- [ ] 描述不符、缺件、空包、运输损坏均可通过通用接入冻结；
- [ ] 完整描述不符模拟案件可从 API 接入并运行到 `HUMAN_REVIEW`；
- [ ] Alembic upgrade/downgrade、API 测试和全量回归通过。

## 非目标

- 不创建真实平台用户认证体系；
- 不接入真实支付、物流和对象存储；
- 不上传图片、视频或二进制文件；
- 不允许冻结后原地修改材料；修正必须通过补证、申诉或新案件完成；
- 不支持一笔交易同时存在多个争议案件。
