# ISSUE-019：实现 Claim 级确定性争议类型 Router

## 背景

第十七、十八步已经提供 Claim 级路由字段和版本化 Skill，但系统尚不能把真实文本主张安全地绑定到对应 Skill。直接让模型决定争议类型会导致分类不可重放、无法解释和难以控制高风险类型。

## 目标

实现一个版本化、可审计、幂等的确定性 Router。模型只能在没有确定性信号时提供候选，候选必须等待人工确认。

## 优先级

```text
审核员覆盖
→ 用户明确声明
→ 平台结构化原因码
→ 确定性关键词规则
→ 模型候选
→ OTHER / 人工分类
```

审核员覆盖是独立管理操作，不允许普通自动路由请求伪造。

## 验收条件

- [ ] 支持描述不符、缺件、空包、运输损坏、假货和 OTHER；
- [ ] 用户声明优先于平台原因码和关键词；
- [ ] 平台原因码优先于关键词；
- [ ] 多个类型同时命中且分差不足时标记 `NEEDS_HUMAN`；
- [ ] 模型候选不能直接变成 `ROUTED`；
- [ ] `COUNTERFEIT` 和 `OTHER` 必须人工处理；
- [ ] Router 只能绑定 Skill Registry 中存在且支持对应 Claim 类型的版本；
- [ ] 重复请求幂等，不重复写入路由历史；
- [ ] 每次路由保存输入指纹、版本、命中信号、理由和内容哈希；
- [ ] 审核员覆盖必须验证身份并保存覆盖原因；
- [ ] 活动调查期间禁止原地改写路由；
- [ ] 未完成路由的 material Claim 不能启动 Agent 调查；
- [ ] 路由结果可通过 API、案件状态和工作台读取；
- [ ] Alembic 迁移、单元测试、API 测试和全量回归通过。

## 非目标

- 不新增正式案件数据集；
- 不新增政策版本；
- 不让模型自由创建争议类型；
- 不支持一个 Claim 同时绑定多个 Skill；
- 不在活动 Case Run 中热切换 Skill；
- 不实现多 Skill 综合裁决，留到第二十步。
