# ADR-0002：Skill 是运行时上下文、补问和 Guard 的执行契约

- 状态：Accepted
- 日期：2026-07-27

## 决策

Claim 路由确定的 `skill_name@version` 不仅用于展示或政策映射，还必须控制四件事：

1. Runtime 可以读取哪些上下文资源；
2. Runtime 和编排器可以调用哪些工具；
3. 规则基线和模型可以提出哪些类型专属补问；
4. Decision Guard 必须执行哪些升级条件和处置边界。

运行时拒绝多 Skill 自动调查。每个 Skill 的实际资源、工具和版本写入 Agent 输入，输入指纹继续参与幂等和重放。

## 原因

- 缺件关注交易内容差异；空包关注重量和打包/开包链；运输损坏关注发货前状态、签收状态和报损时效。共享全部上下文会增加无关信息和错误归因机会；
- 工具白名单是最简单可审计的权限边界；Prompt 中的“不要调用某工具”不够可靠；
- 不同争议需要不同补问对象和证据类型，投票不能代替调查方法；
- 金额、责任归属和强制人工条件必须由确定性代码检查，不能只依赖模型遵循 Manifest。

## 取舍

- 当前限制为一个 material Claim 集合绑定一个 Skill；复合案件先拆分 Claim 或转人工；
- 规则基线为三类文本 Skill 提供安全默认：无法从证据取得金额时转人工，不自行按市场价格估价；
- `empty-package` 的全额退款不创建退货动作，因为争议假设没有可退的交易商品；
- `shipping-damage` 默认不把物流异常直接转换为卖方责任，除非有包装不足等责任证据；
- 视觉证据仍可作为允许的证据类型，但本步只处理已提取的文本事实。

## 后果

新增 Skill 必须同时提供 Manifest、政策族、专属 question rules、Guard Profile 和 Fixture。修改任何一项都应升级 Skill/政策版本并通过 PR 评审。
