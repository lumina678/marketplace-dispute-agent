# ADR-0001：争议类型使用确定性 Router，模型只提供候选

- 状态：Accepted
- 日期：2026-07-26

## 决策

Claim 路由由版本化配置和确定性代码完成。用户声明、平台原因码和文本规则按固定优先级执行；模型输出只能作为候选，必须进入人工确认。所有最终绑定都指向不可变的 `skill_name@skill_version`。

## 原因

- 相同输入必须产生相同结果，支持重放和申诉；
- 争议类型会决定证据要求、政策范围和允许结果，不能由不可审计的自由生成直接控制；
- 假货、未知类型和复合主张具有更高风险；
- 规则配置可以独立评审、版本化和回滚；
- Agent 仍可用于提取候选，但不能越过确定性边界。

## 被否决的方案

### 完全由大模型分类

实现简单，但模型升级、Prompt 变化和服务商差异会改变路由，无法可靠重放。

### 只使用关键词，不允许模型候选

安全但覆盖不足。保留模型候选可以帮助人工分类，同时不授予自动绑定权限。

### 一个 Claim 同时运行多个 Skill

会扩大上下文、政策和 Guard 组合复杂度。当前选择“一个 Claim 一个 Skill”；复合陈述应拆分 Claim 或转人工。

## 后果

- 新 Skill 必须先注册，Router 才能绑定；
- 规则和阈值升级必须增加 Router 版本；
- 低置信度会降低自动推进率，但提高安全性和可解释性；
- 第二十步编排器可以直接依赖已锁定 Skill，而无需再次分类。
