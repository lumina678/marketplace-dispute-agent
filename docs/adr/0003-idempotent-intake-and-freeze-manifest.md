# ADR-0003：通用接入使用幂等业务 ID 和冻结 Manifest

- 状态：Accepted
- 日期：2026-07-28

## 决策

通用案件接入采用两阶段模型：

1. `SUBMITTED` 阶段允许导入商品、聊天、Claim 和初始文字证据；
2. `freeze` 原子完成路由确认、政策固定、快照锁定、系统证据生成和 Manifest Hash，然后进入 `EVIDENCE_LOCKED`。

所有资源由调用方提供稳定业务 ID。相同 ID 和相同规范化内容是幂等重放；相同 ID 和不同内容是冲突。聊天批次在单个事务中全部成功或全部回滚。

## Manifest 范围

Manifest 包含：

- 交易字段；
- 商品快照 ID、时间和内容哈希；
- 聊天 ID、时间和内容哈希；
- Claim 陈述哈希、当事方、时间和响应关系；
- 冻结时已有证据的 ID、时间和哈希；
- 固定政策 ID、版本和依据时间。

Manifest 本身再次计算 SHA-256，保存到案件和状态事件中。后续补问或申诉证据不属于初始 Manifest，它们以追加式证据和新 Case Run 审计。

## 权限边界

- ADMIN：创建模拟交易、导入平台商品和聊天；
- BUYER/SELLER：只能提交本交易、本方 Claim 和本方文字证据；
- REVIEWER/ADMIN：执行冻结；
- 冻结后所有基线写接口关闭；补证和申诉继续使用已有专用接口。

## 被否决的方案

### 直接复用种子脚本

无法提供 API 契约、权限、幂等、冲突检测和并发控制，不适合部署后给外部使用。

### 允许 PUT 覆盖快照

会破坏政策选择、Agent 输入指纹和申诉重放。修正应创建新证据或新案件，不覆盖历史材料。

### 只保存文字证据摘要

Agent 无法复核原始文本。当前在 SQLite 保存最多 100,000 字符原文；未来接对象存储时可保留相同哈希和 URI 契约。

## 后果

- 新增 `Evidence.content_text` 和案件 Manifest 字段，需要 Alembic 迁移；
- 冻结前未完成分类的案件必须先人工覆盖路由；
- 当前每笔交易最多一个争议案件；
- API 中的 actor ID 仍是模拟身份，真实认证与 RBAC 留给后续步骤。
